The Dungeon Mastron console is Dungeon Mastron, made physical: a 3D-printed, Raspberry-Pi-powered machine with real buttons, real LEDs, and cartridges you label yourself. Built from parts anyone can buy – everything understandable, everything replaceable.

Where it honestly stands: version 1 of the case is printed and working; the Pi game engine runs but hasn’t been thoroughly tested yet. This is a beta – build one, break it, tell us what happened.

01 The build

No custom chips.

A / What it's made of

A DIY build from accessible parts and simple electronics.

  • 3D-printed enclosure
  • Physical buttons + LEDs for tactile feedback
  • Raspberry Pi at the core
  • Official Raspberry Pi 7″ screen
  • Basic electronic parts – that's it

B / Same games, everywhere

One game format. Two ways to play. Every game runs identically on console and web player.

  • Build once
  • Play instantly in the web player
  • Load the exact same file onto the console
  • No forks, no downgraded experiences

C / Files & availability

All build files and resources are freely available:

  • Right here, on GitHub
  • On MakerWorld
  • Print it, tweak it, remix it, rebuild it

D / The difference

The platform doesn't change what you play between screen and shelf.

  • The web is the invitation
  • The console is the aspiration
  • The difference is how it feels to play

03 The cartridge

One story.
One cartridge.

A complete world, made physical. Every game you create can live on its own cartridge – swap them, shelve them, trade them.

  • 3D-printed, designed to be reused and re-labeled
  • Houses a USB drive holding the complete game
  • One adventure per cartridge
  • Easy to swap, store, and share
  • Works on any Dungeon Mastron console

The same game file that runs in the web player loads onto a cartridge without modification.

Open source & community beta. All hardware designs, the system image, and the Python runtime are freely available on GitHub. The case is at version 1 and the engine is still proving itself – for this console to become what it could be, a community needs to form around it: testers, feature-builders, engine-polishers, and anyone who wants to redesign the shell entirely. Build one, remix it, improve it – it’s yours to shape.
